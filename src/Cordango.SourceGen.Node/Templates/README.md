## Run it

```sh
docker compose up --build
```

Open <http://localhost:8080>. The first screen asks you to create the administrator account.

That is the whole deployment: no `.env` to write first, no migration step, no password to look up.

## Run it without Docker

```sh
cd api  && npm install && npm run build
cd ../web && npm install && npm run build
cd ../api && APP_SECRET=$(node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))") npm start
```

With no `DATABASE_URL` the application runs on PGlite — a real PostgreSQL, compiled to run inside
this process, storing to the local disk. Nothing to install and nothing to start. Point
`DATABASE_URL` at a server when you want one; both speak the same dialect, and no code above the
driver knows which it got.

While you are working on the front end, run it on its own instead — Vite serves it with hot reload
and proxies `/api` to the application:

```sh
cd web && npm run dev
```

## Changing it

Everything here is ordinary source. Add an endpoint, change a screen, put a package in
`package.json`.

Regenerating replaces the files a build owns and leaves everything else alone.
`cordango.build.json` lists exactly which files those are — so the safe place for your own code is
any file that is not in that list. `server.ts` is not in it: the host is yours from the first build.

## Configuration

Every setting is an environment variable, and `.env.example` documents all of them. Two matter
before this goes anywhere real:

- **`APP_SECRET`** signs the session and antiforgery cookies. `docker-compose.yml` defaults it to a
  value that is fine on a laptop and nowhere else. Anybody who knows it can forge a session for any
  account here.
- **`SECURITY_REQUIRE_HTTPS`** marks those cookies `Secure`. Turn it on once there is TLS in front
  of the application — and not before, because a browser will not send a `Secure` cookie back over
  plain HTTP and the symptom is a sign-in that appears to work and leaves you signed out.
